# 90日の発信カレンダー（2026年11月9日〜2027年2月7日・13週）

## 考え方

- **note**：2週に1本のペースで、記事①〜⑤と固定記事を出す。作業は土日にまとめて行う（平日の日中は本業のため）
- **X**：週に2〜3本。平日の投稿は、前の週末に予約投稿でまとめて設定しておく
- **流れ**：役に立つ記事・小ネタで知ってもらう → 見本で「どんな物が届くか」を見せる → パッケージを案内する。案内（P）は、関連する記事や見本を出した翌週に置く
- **時期に合わせる**
  - 11月中旬：3月決算の上場企業の中間決算の発表が一段落する時期 → 記事③（取引先の財務チェック）
  - 12月：賞与と年末の支払いが重なる時期 → 記事②（資金繰り表）
  - 1月：年明けの業務見直しと、確定申告の準備の時期 → 記事⑤（Excel自動化）、F（記帳まとめ入力）
  - 2月：確定申告の期間（例年2月中旬〜3月中旬。2026年分の正確な日程は国税庁の発表で確認する）の前 → F をもう一度案内
- 投稿番号は `x_posts.md` のもの（T＝小ネタ、S＝見本・実績、P＝パッケージ案内、N＝note記事の告知）

## 毎週やること（土日に30分ほど）

1. 翌週の X 投稿を予約投稿で設定する
2. ランサーズのメッセージを確認し、購入前の相談に返信する（平日夜・土日の範囲で、できるだけ24時間以内）
3. note のビュー数・スキの数と、X の反応（表示回数・プロフィールへのアクセスなど）を、表に1行メモする

## 毎月の振り返り（第4週・第9週・第13週）

| 見ること | どこで見るか | 次の行動の例 |
|---|---|---|
| よく読まれた記事・投稿のテーマ | note のダッシュボード、X のアナリティクス | 反応の良いテーマで、次の記事や小ネタを増やす |
| パッケージの閲覧・お気に入り・相談の数 | ランサーズの管理画面（見られる範囲で） | 見られているのに相談がないパッケージは、タイトル・1枚目の画像・ベーシックの内容を見直す |
| 記事からパッケージへの流れ | 記事の最後の案内の書き方 | 案内の位置や文面を変えてみる |

数字は自分の振り返り用です。記事や投稿の中で「◯件受注」などの実績として書くのは、実際の数字が出てからにし、作った数字は使いません。

## 投稿の前に確かめること（毎回）

- [ ] 資格を名乗っていない（税理士・公認会計士・FPなど）
- [ ] 実績の件数・成果の数字を作っていない
- [ ] 税金の計算や節税の個別の相談に答える書き方になっていない
- [ ] 「適正です」「問題ありません」など、監査や証明のような書き方になっていない
- [ ] 特定の株の売買をすすめる書き方になっていない
- [ ] 「必ず」「絶対」「No.1」など、根拠のない強い言葉を使っていない
- [ ] ご依頼の窓口をランサーズにしている（XのDMやメールで直接受けない・連絡先を書かない）
- [ ] 価格・納期が、ランサーズの出品ページと一致している
- [ ] 他社や制度について書いた部分に、出典がある
